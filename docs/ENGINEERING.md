# 技术复盘

## 先明确哪个环节耗时

一次“识别很慢”可能包含相机打开、丢弃旧帧、图像编码、网络往返、模型处理、结果校验和语音播放。把总时长全部归到模型，会优化错地方。这里将识别与播放器状态分别记录；更换模型时也应保存同一批输入、正确答案、端到端耗时和token用量，再看中位数及长尾，而不是只展示最快的一次。

本包保留兼容视觉API的单图客户端。默认模型是当时项目使用的配置，不是最新模型推荐或速度保证。不要把标准答案写进识别返回值；失败时应明确拒识，再拍新图或停止。

## 固定图集可以走本地，但必须能拒绝

如果图集来自自己拥有使用权的固定模板，可以先做ORB特征、汉明距离匹配和RANSAC单应性检查。实现分别验证上方文字区和下方图案区，要求两区满足同一几何关系，避免只认到水果就把整张卡当成正确答案。

多候选接近、多张卡同时可见、内点不足或几何不合理时应拒绝。ROS混合模式保留连续帧稳定要求，本地不确定时再进入API服务。模板渲染图上的高通过率，不等于现场光照、反光和遮挡下的准确率。定时路线当前使用相机API链路，不因为仓库里有匹配器就自动变成本地优先。

## 预生成音频把网络依赖从播报移走

编号组合有限时，可以预先录制WAV，识别后只选择对应文件。播放前核对文案、文件哈希和PCM格式；识别结果不应决定任意文件路径。音频缺失或播放失败必须有明确状态，不要把“程序没报错”说成观众听到了。

结束语是按任务顺序播放的本地提示，不是独立的终点传感器。定时路线走完不能证明整车进入终点区域。

## 不要把四种状态混在一个success里

| 层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 请求已接受 | 控制软件接受请求 | 后台已执行完成 |
| 脉冲软件完成 | 写入及STOP清理按软件约定结束 | 机构实际出弹 |
| 机构动作 | 需要独立观察或传感器 | 靶上命中 |
| 命中 | 需要靶标、裁判或其他独立证据 | 不能由串口字节数代替 |

失败时保留阶段记录，不自动补射，也不从起点重跑整个任务来“重试识别”。否则同一条重试命令可能重复先前已经完成的运动和机构动作。

## 部署问题和算法问题分开排查

`/dev/shoot` 不存在时，优先查设备枚举、供电、连接和别名规则；删掉预检不会修复设备。端口有写权限也不能证明设备身份正确。相机编号、声卡名称和USB串口编号都不应猜测。

ROS1旧环境尤其需要核对Python绑定、工作空间绝对路径和旧build/devel缓存。把文件夹改名后直接复用旧setup，可能继续加载旧目录。现场包使用ASCII路径，并在新位置重建环境；不要同时启动原厂家控制节点和直接串口入口。

## 取舍

闭环方式更适合有定位、传感器反馈和充分联调条件的系统；定时方式依赖固定场地与重复标定，能缩短集成链但不能代替导航。技术复用应落在任务分层、参数组织、拒识策略、执行状态和诊断方法上，而不是复制一组比赛距离。
